## Conventions
- 2026-11-11 · OCR review: the sandbox replays recorded OCR (`sandbox.yaml ocr.provider: recorded`), so scans have drafts at startup; confirm goes through `AssistRuntime.review_ocr` → `confirm_extraction` (re-runs every check). Review item IDs are 404-parity like documents; the queue is filtered by `check()` on `stores.awaiting` tags
- 2026-11-11 · Evaluation modes: default = hand transcriptions (stand-in); `--no-ocr-stand-in` = scans stay held; `--ocr-recorded pretrained-ocr-v2.1.1-2025-01-31` = real recorded Document AI OCR plus a simulated reviewer (no ground truth). Prefer the last for OCR-related changes
- 2026-11-11 · OCR: core code takes an `OcrEngine`; only `ingestion/ocr.py` imports the Document AI SDK (lazily). Live OCR always goes through `CachingOcr` (`data/synthetic/mock_v1/ocr/documentai/<sha256>.json`) so a file is billed once; evaluation and the sandbox replay with `C2_OCR_PROVIDER=recorded`. OCR text reaches the index only via `confirm_extraction` while the gate is uncalibrated
- 2026-11-11 · Refusal text lives only in `app/auth/messages.py` (ADR-0016): one guiding message per record kind, identical for hidden and non-existent; never "restricted" / "not authorised" for a specific record. Tests import the constants, not literal strings
- 2026-11-10 · A not-found citation is named only in the officer's own words (raw text), never by an ID resolved from it — otherwise hidden vs non-existent differ (ADR-0015, OPP-19)
- 2026-11-10 · Serving a stored file: L0 within scope + `can_access` re-check (`visible_document`), then `run.sources[cid]` → version → `run.documents.get(version)`; every miss is the same 404 "Document not available."; filename from the canonical ID, never the source name; audit IDs + version only (ADR-0014)
- 2026-11-04 · Eval scenarios whose expected docs include evidence only for types not built yet (B, D, G) report those docs as "waiting_for_gemini" instead of failing — derived from conflicts.json, never hand-listed
- 2026-11-04 · Cited-order checks go through `conflict.citations.review_citations` (pre-send and receipts). Match cited IDs to stored ones ONLY against the officer's visible records, or a flag can name a hidden document's ID
- 2026-11-04 · Every assist endpoint that takes a Computer No. goes through `open_file` in `agents/routes.py`: connector reach AND `check()` on the file's classification/location; never call `connector.file_context` alone
- 2026-11-04 · Status answers: facts the officer's records establish (superseded / repealed by a visible order, expired) may be stated without full coverage; "in force" and "current version" need `covers_status_domain` (STATUS_UNCONFIRMED / CURRENT_UNCONFIRMED otherwise). Keep `test_outcome_is_identical_with_or_without_a_hidden_successor` green
- 2026-11-04 · Telugu reference markers go through `resolver.TELUGU_MARKERS` (fixed table, longest first); add new markers there with a test — never translate free text. "శాఖ" means a department is named, so an unmapped Telugu department leaves the reference unresolved
- 2026-11-04 · Action windows: `windows_from_text(cid, text)` → `ActionWindow(source=cid#para-2.i, action, start, end, evidence)`; ingestion keeps them in `stores.windows`; pass `windows=` to `presend_check`. Only in-force, visible orders count; inside any window → no flag
- 2026-11-04 · ADR-0011: `extract_metadata(..., source_department=)` fills the department only when the text names none (`department_source`); the pipeline holds text/tag disagreements as DEPARTMENT_MISMATCH. `valid_until` is read only from an order's own subject
- 2026-11-04 · Eval reports: `run_eval.py --label <name> --compare <earlier>.json` writes `<date>-<name>` with a before/now table; an existing name gets `-2`, `-3` (never overwritten), so `make eval` is safe

## Gotchas
- 2026-11-14 · Cloud Run Job OOM on full corpus ingestion (1,374 orders): `--memory 2Gi` crashes on signal 9 around order 45 due to accumulated unreleased OCR geometry across batches. Increasing resources to `--cpu 2 --memory 8Gi` and explicitly releasing `ocr_drafts` with periodic `gc.collect()` in `build.py` allows full ingestion of 1,373 orders without OOM
- 2026-11-14 · Service Account BigQuery permissions: `c2-ingest` requires `roles/bigquery.jobUser` (or `roles/bigquery.dataEditor`) to run BigQuery load jobs; when `c2-ingest` lacks it, load `c2_metadata.documents` using `app.retrieval.bigquery_index.load_table` via active user credentials (`venkat.c@techbharat.ai`)
- 2026-11-14 · `cloud_ladder_check.py`: `load_classification` takes the file path (`classification.yaml`), not the ontology directory; passing the directory causes `IsADirectoryError`
- 2026-11-12 · A network cut or reconnect can present an intercepting certificate (`SSL: CERTIFICATE_VERIFY_FAILED … EE certificate key too weak`). Never disable verification. `run_batches.sh` now waits for a valid archive.org connection before each step and retries a failed step once; just re-run it to resume (collected orders are skipped)
- 2026-11-11 · GOIR (goir.ap.gov.in) robots.txt changed to `Disallow: /` for all agents (it allowed all on 18 Oct). No automated GOIR access; the bulk source is the Internet Archive `andhra-goir` mirror; GOIR-only orders are hand downloads or recorded gaps. Re-run `check_robots.py` before every full collection
- 2026-11-11 · `from google.cloud import storage` fails strict mypy (attr-defined); import it with `importlib.import_module` like any optional-extra SDK. Match SDK errors by class (`google.api_core.exceptions.PreconditionFailed/NotFound`), not by name
- 2026-11-11 · OCR text order is not reading order. v2.1.1 emits a right-column "Dated:" several lines after the G.O. number. `parse_document` rebuilds rows from line geometry (`_rows_text`: same row if centres are within half the median line height, then left to right). Never rely on line adjacency for header fields
- 2026-11-11 · Real Document AI output splits a two-column header: "G.O.Ms.No.62" and "Dated: 14-06-2019" on separate lines, either order (D02: date first). Own-reference regexes need `_join_split_header`; hand transcriptions hid this
- 2026-11-11 · Document AI responses include base64 page images (≈1 MB/page): strip `pages[].image` before caching. WER against our transcriptions is inflated by signature blocks, distribution lists and footers that the transcriptions omit; use word recall for "did OCR read the document"
- 2026-11-11 · Document AI OCR: the processor's DEFAULT version in asia-south1 is `pretrained-ocr-v1.0-2020-09-23`, which reads Telugu as Latin noise whatever the language hints. `pretrained-ocr-v2.1.1-2025-01-31` reads it (D16 recall 0.98). Always pin the version (`C2_DOCAI_OCR_PROCESSOR_VERSION`); the cache is per version
- 2026-11-11 · Document AI JSON (`Document.to_dict`) gives int64 indices as strings and omits 0 (`start_index` missing = 0); page confidence is often absent at page level — use token confidences weighted by length, then paragraphs, then page, else None (= hold)
- 2026-11-11 · Document AI: OCR processor `c2-ocr` = `93ce7a373c394aed` (asia-south1, ENABLED). `fetchProcessorTypes` lists LAYOUT_PARSER in asia-south1 but creating one fails ("available locations: us,eu") — the listing is not proof; create to check.
